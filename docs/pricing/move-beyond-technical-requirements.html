1. Product overview and scope

Move Beyond runs padel, tennis (including nations team events), chess and other racket/game-sport competitions. The system has three surfaces that share one backend:

SurfacePurpose
Tournament System (web)Admin console for organisers: create events, teams, draws, schedules, courts, results, rankings, leagues, registration, messaging, screens. Public pages for fans. Referee web console.
Move Score (mobile app)Fan and player companion: live scores, order of play, draws, alerts, following, event pass, lock-screen live scores, widgets, registration and payment, player profile. Also the referee/umpire scoring console for officials.
Venue screensCourt-side TVs and big screens: live score, walk-on, line-ups, results, rankings, sponsor loops, QR codes — remotely controlled by an operator.

Scope: inside the court (scoring, rules, umpiring, voice calls, court calls, no-shows) and outside the court (registration, payment, schedules, fans, alerts, screens, sponsors, rankings, leagues, organisations, messaging). Language: English UI. Time zone default Africa/Cairo, per-event time zone supported.

2. Users, roles and organisations

2.1 Multi-tenant organisations

  • Clubs, academies and organisers apply online; the platform owner approves, rejects, suspends or creates organisations directly.
  • Each organisation owns its tournaments, sessions, leagues, seasons, ranking categories, announcements and players; strict data isolation between organisations (one organisation can never read or change another's data).
  • Organisation profile: name (renames approved by the platform), logo (validated upload), colours, about, city, country, venues; branding feeds the app skin of its events.
  • Billing fields per organisation: plan tier, commission %, subscription status (recorded; billing engine optional in quote).
  • Public organisation page in the app; fans can follow an organisation.

2.2 Roles and access

RoleCan do

Organisation owner / adminEverything inside the organisation; members and invites; refunds; branding.

2.3 Staff authentication

  • Personal staff accounts (Google sign-in or email + password) with a server-signed session cookie; membership re-checked on every request so removal/suspension is immediate.
  • Event access codes for referees and operators: random, stored hashed, optional scope to one tournament, expiry, instant revocation, shown once.
  • Signed, single-use, email-bound invite links (7 days) with an explicit "Join … as …?" confirmation.
  • Members page with role rules (only owners create owners/admins; last owner protected at database level).
  • Legacy shared role passwords for the platform owner's organisation (transitional).
  • Rate limiting on every login path (atomic counters, per address and per code prefix, failures only).

3. Tournament management (web admin)

3.1 Events

  • Create, edit, clone (copy structure, rules and branding), archive tournaments; status draft / active / completed; public or private.
  • Event groups (several tournaments under one event, e.g. boys' and girls' finals) with featured ranking.
  • Venue, city, country, first/last day, first-match start time, time zone, artwork, app skin colours, light/dark preference, player photos on/off.
  • Courts per event with order and names.
  • Sponsors and branding configuration (logos shown on public pages and screens).
  • Excel export of the whole event (teams, matches, results, audit).

3.2 Teams and players

  • Teams (pairs or squads), players, photos with focal point, nations (ISO flags), captains.
  • CSV import of teams/players with downloadable template.
  • Private player data (phone, email, access code) never exposed on public pages, screens or referee phones.
  • Per-tournament player access codes (send via WhatsApp/email, reset, CSV) for players to link their app account.
  • Global player database with approval, notes, level, categories (private per organisation), merge of duplicates (platform-admin only).

3.3 Draws, groups, brackets and schedule

  • Group stage with round-robin generation, manual/locked group assignment, standings with configurable tie-breakers.
  • Knockout brackets: slots, seeding, byes, automatic advancement and retraction when results change; main draw and Plate / consolation brackets, bracket tiers; placement draws for every place (1–16).
  • Leaderboard / standings snapshots; winner page.
  • Order of play: court + time per match, manual matches, "delay the order of play" for rain/overruns (shifts everything after a time).
  • Check-in of teams; QR check-in per match.

3.4 Tennis nations team competitions

  • Ties between nations made of rubbers (Singles 2, Singles 1, Doubles); tie score; per-tie court and not-before time.
  • 2026 ITF team regulations: singles nominated before play with order-of-merit check (No. 1 above No. 2); doubles "to be named" until after the singles; late changes need an audited reason; locking needs only the singles; dead rubbers still played; ITF group ranking (head-to-head of two; then matches won, sets %, games %); placement lots entered by the desk; short-format singles below the main draw (two sets + 10-point match tie-break) per match; warning when a retired player is named again.
  • Real event loading script (32 nations, 96 players, 32 captains) as drafts.
  • Finals replay tool for demo events (turn a real score line into engine-verified points).

3.5 Admin quality-of-life

  • Every expected refusal shown inline next to the button (no error pages); every state change written to a per-organisation audit log (actor, organisation, role, before/after).
  • Admin Match day tab, App tab, Screens tab, Registrations tab, Players / Player codes tab per tournament.
  • Platform Discover page: order of featured events and live tournaments in the app, global feature flags.

4. Sports, formats and scoring engines

4.1 Sports registry

SportEngineSupports
PadelGames & setsShowcase, final-result entry, "match soon", Live Activities, voice umpire
TennisGames & setsAll of the above + nations team ties, doubles rules
ChessWin / draw / loss per gameFinal-result entry, knockout with arbiter decision, chess moves on web console
Any other games sportGeneric games & setsConservative feature set (one configuration entry per new sport)

4.2 Rules engine

  • Configurable per tournament, per stage, per match: sets to win, games per set, tie-break at N-N, tie-break length, golden point / no-ad, advantage sets, short sets, Fast4, pro sets, super / match tie-break instead of a deciding set, sudden death.
  • Serve rotation, change of ends, tie-break serve order; disqualification, retirement, walkover endings.
  • Pure, framework-free engine shared by server, web console and mobile app; property-tested against thousands of random matches.

4.3 Scoring modes

  • Point by point (live), final result only, or either (referee picks) — set per tournament, session or match.
  • Final-result entry: side-by-side set entry, tie-break points required for 7-6, summary with winner highlighted, "Confirm / Keep editing", second confirmation; server rebuilds and verifies the result.
  • Corrections of finished matches by organisers only, audited, with automatic update of standings, brackets, league points.

5. Live scoring — referee and umpire consoles

5.1 Consoles

  • Web referee console and native mobile console (same rules, same engine).
  • Large-target point buttons, undo, pause/resume, first server selection, retirement/walkover/DQ, red/blue team identity, sunlight (high-contrast) mode, dark/light.
  • Offline-first: points queue on the device and sync in order when the signal returns; conflict handling (409) with "load the server's score".
  • Scoring lease / device lock: one device controls a match; request and hand over control between referees; lease renewal and release.
  • Referee access by event code; list of assigned tournaments and matches.

6. Match day operations

  • Match day rules per tournament/session: showcase on event days, player alerts, "match soon", court calls, no-show policy, Live Activities, widgets, scoring mode, extras.
  • "Match may start in ~5 minutes": sent once when the match before on that court is one game from finishing (respecting each format's rules), to the players of the next match; never for undecided sides or players still playing on another court.
  • Court call: when the referee opens the match the players are called to court with a countdown (default 5 min), reminder at −2 min, presence per side, "I'm at court" button for players, QR check-in marks presence.
  • No-show prompt: keep waiting, extend +5 min (configurable maximum), walkover to the side present; both absent → organiser decides.
  • Abuse limits (call/extend/cancel rate limits, one alert per 10 minutes).

7. Public web platform

  • Per-tournament public site: overview, live, matches, match detail, bracket, leaderboard, nations ties, winner page.
  • Friendly session pages with rankings and online registration.
  • Public rankings (lifetime / season, per organisation).
  • Registration pages, payment status page, email confirmation flow.
  • Move Score product pages: home, Android direct download (APK), support/FAQ, privacy policy, terms, account deletion.
  • Auto-refresh / polling live updates; CDN-cached public data (2–60 s) with private per-user routes never cached.
  • Universal links (app opens from links), short links for venues and matches.

8. Venue screens (TVs) and screen control

  • Unlimited named screens per event (e.g. Court 1 TV, main hall wall), each with its own scene settings, both brackets option, uploads (backgrounds, sponsor images).
  • Automatic scene engine for tennis ties per court: line-up → walk-on → live score → rubber won → tie score; padel/one-match fixtures: live score, result, next on court; night tables; rankings; bracket; winner.
  • Nation flags, player portraits with focal point, sponsor logos, QR codes (venue pass, match check-in).
  • Operator control panel: remote scene switching per screen, presence (which screens are online).
  • Takeover animations for results; reduced-motion support.

9. Voice umpire

  • Automatic spoken score calls on the referee device / speakers: points, games, sets, deuce, advantage, deciding point, tie-break, match tie-break, change of ends, time, nation names; red/blue team naming.
  • Pre-rendered neural voice packs (versioned), fallback pack, per-call support detection.

10. Move Score mobile app (iOS & Android)

10.1 Fans

  • Discover: featured events and live tournaments in an admin-controlled order; Live courts showcase at the top on event days — swipe per court: walk-on with player photos, live score, result card, "next on court", court call countdown; the user's own match pinned first.
  • Tournament screens: order of play, matches, live scores, draws/brackets, standings, ties, nations, teams, players, match timeline (point history), share cards/stories.
  • Following players, nations, ties, matches, tournaments, organisations — without an account; merge on sign-in.
  • Alerts per category (scheduled, starting, finished, court calls…), quiet outside event days.
  • iPhone Live Activities (lock screen / Dynamic Island) with phases soon → called (countdown) → live → final; push-to-start for the player's own and starred matches.
  • Home and lock-screen widgets ("My matches").
  • Cheering for nations in ties (cheer counters).
  • Accessibility (screen reader labels, large type), calm/reduced motion, dark/light themes, offline cache.

10.2 Accounts

  • Guest by default; sign in with Apple, Google, email + password (confirmation, reset, one-time codes) or a player code.
  • Account deletion in app (Apple guideline 5.1.1(v)) incl. Apple token revocation.

10.3 Players

  • My profile: tournaments, nights, leagues, results, points, ranks; link history by player code, WhatsApp one-time code (email fallback after asking), organiser offer, email match.
  • "I'm at court", own-match alerts, registration and payment, my registrations, refund request.

10.4 Officials

  • Referee console inside the app (see §5), call card, no-show sheet, final-score entry, offline queue.

10.5 Distribution

  • App Store and Google Play builds, ad-hoc/internal builds, direct APK download page, over-the-air config flags (feature switches without a new build), minimum supported version.

11. Players: identity, profiles and history

  • One global profile per person across all organisations and events; per-organisation private data (approval, notes, level, categories).
  • Player codes stored only as keyed hashes (+ sealed copy for organisers to resend); one-time codes 6 digits, 10-minute expiry, attempt limits, per-phone daily guess budget.
  • Strict anti-takeover rules (codes never link another organisation's rows; email proofs link only rows with matching phone and email; masking of contacts and photos for organisations that only matched a number).
  • Archive of a player's link to an event 24 h after it ends; results kept forever.

12. Leagues, rankings and boards

  • League kinds: recurring nights or season fixtures (dated round robin per division, regenerate unplayed fixtures).
  • Divisions; editable points rules (default win 2 / loss 1, walkovers, optional win-streak bonus, draws for chess).
  • Boards: monthly, 3/6/9/12-month sums, configurable year start; per-organisation and platform-wide "Top of all leagues" (normalised scale, organisations can opt out).
  • Joining: open / organiser approval / invite code / paid (pay at venue or online); tournaments can count toward a league division.
  • Visibility: everyone / organisation's players only / invite-only (code reveals the league).
  • Lifetime and season rankings per organisation, ranking categories, ranking models.

13. Americano / Mexicano social nights

  • Friendly sessions: Americano and Mexicano rotation scheduling, entries/approvals, pairs, Mexicano next-round draw, session ranking ("fire" streak).
  • "Confirm players and publish table": per-court order of play with "about 19:40" time estimates that re-estimate as matches finish; table on web, TV, app and league pages; alerts to players.
  • Nights created from a league's night template with a date; public registration with photo.

14. Registration and online payments

  • Per event: entry type individual / team / both, team size, approval mode (first paid, first in default, or organiser approval), fee per player, payment online / at venue / player's choice / free, who pays for a team, capacity, closing time, note.
  • Guests confirm by email link; app users need a confirmed email; capacity enforced atomically (confirmed entries + 15-minute checkout holds).
  • XPay card payments (hosted checkout, signed webhooks, async/Fawry-style payments, refunds via API, 50 EGP card minimum); alternative partner integration with the Move Tick ticketing platform.
  • Refunds always 100 %, allowed until 24 h before the start time; overflow/duplicate payments flagged for refund at any time; audited.
  • Admin: registrations list, approve/refuse, pair solo players, mark paid at venue, refund by payment.

15. Messaging

  • Push notifications (Expo/APNs/FCM) with categories and per-device preferences; scheduled sends (reminders) via a cron-driven drain.
  • Announcements console: audiences (tournament, nation, all players, followers, pasted list), email via Resend (branded layout), WhatsApp Cloud API templates, one delivery row per recipient per channel, delivery tracking via webhooks, CSV export, test sends, dry-run mode.
  • Transactional messages: registration, payment, refunds, invites, player codes (codes never stored in message logs).
  • Branded email templates for authentication (generated, versioned).

16. Event pass, venue check-in and wallet passes

  • Collectible digital event pass per user per event; stamps for each day attended by scanning a rotating venue QR code on the screens; pins and points.
  • Apple Wallet pass (signed .pkpass) and Google Wallet pass.
  • Match QR check-in for players.

17. Security, privacy and compliance

  • Database row-level security: public keys can read nothing; all access server-side with a secret key.
  • Tenant isolation enforced on every admin action, page and API (organisation resolved from the record, never from user input); automated attack test suite (~1,000 cross-organisation attacks).
  • Secrets and codes stored only as peppered HMAC hashes; AES-GCM sealing where a code must be re-sent; signed cookies (__Host-), CSRF/origin checks, rate limits, identical answers for "not found" and "not yours".
  • Signed webhooks with replay windows and idempotency (payments, email, WhatsApp).
  • Private player data masking; privacy policy, terms, account and data deletion; consent tracking for WhatsApp/marketing.
  • App Store / Google Play compliance (account deletion, privacy labels, Sign in with Apple).
